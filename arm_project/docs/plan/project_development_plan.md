# 机械臂视觉项目开发方案 (基于睿尔曼RM65-6F + D435i)

## 1. 项目概述与需求分析
本项目旨在基于 **睿尔曼 (Realman) RM65-6F 协作机械臂** 和 **Intel RealSense D435i 深度相机** 开发一套视觉引导控制系统。
**核心任务**：
1. **图像识别**：实时画面中共有 4 根电缆上下排列，需识别并剔除最上方的备用电缆，然后定位剩余的上、中、下三根工作电缆。
2. **上位机通信**：接收上位机指令，确定目标电缆（例如“靠近中间电缆”）。
3. **视觉伺服与避障**：机械臂规划路径靠近目标电缆，同时利用深度相机进行实时的三维视觉避障，防止机械臂在移动过程中碰撞到其他线缆或环境障碍物。
4. **工程管理**：使用 `pdm` 进行现代化的 Python 项目依赖和虚拟环境管理。

---

## 2. 系统架构设计

### 2.1 硬件架构
*   **执行机构**：睿尔曼 RM65-6F，提供 6 自由度灵活运动及丰富的 API 控制。
*   **视觉传感器**：Intel RealSense D435i，提供高质量 RGB 图像及深度 (Depth) 点云数据，内置 IMU。
*   **安装方式**：推荐采用 **眼在手上 (Eye-in-Hand)** 安装方案，即将 D435i 安装在 RM65-6F 末端法兰处。这有利于在靠近电缆时获取高精度的局部视野，并且在移动中提供实时的前方避障深度信息。
*   **计算单元**：NVIDIA Jetson 系列边缘计算节点（基于 **JetPack 6.2**），运行 Python 算法程序。

### 2.2 软件栈与技术选型
*   **语言**：Python 3.10+
*   **包管理器**：`pdm`（PC开发端统一锁定依赖，Jetson 实机端通过 `--index` 独立拉取专版 PyTorch 解决跨平台版本断层问题）
    > **部署细节**：有关 Jetson 环境配置及 D435i / RM65-6F SDK 的编译安装详细说明，请参考独立文档 [环境依赖与部署指南](../environment_setup.md)。
*   **核心算法库**：
    *   `pyrealsense2` (>=2.54.1)：获取 D435i 彩色图、深度图和内参（通过 PDM 隔离打出的本地轮子引入）。
    *   `opencv-python` (>=5.0.0.93)：传统图像处理、轮廓提取。
    *   `ultralytics` (YOLOv8)：用于训练和推理电缆的实例分割/目标检测。
    *   `numpy` / `scipy` (>=1.15.3)：矩阵运算、齐次变换、机器人运动学。
    *   `Robotic-Arm` (>=1.1.6)：睿尔曼底层 C-API 的 Python 控制句柄。

## 4. 核心算法方案

### 4.1 电缆识别与排序 (Vision Detection)
1. **基于 RGB-D 标准融合架构的 YOLO 检测与多段碎片重聚类 (RGB-D Fusion YOLO & Clustering)**：
    *   **架构升级**：为彻底解决深度图无法通过纹理和颜色区分“电缆”与“固定夹具 (Clamp)”的痛点，系统摒弃纯深度检测，切换为 **RGB 图像目标检测 + 深度图测距** 的融合架构。
    *   即使在不外加补光灯的弱光环境下，凭借 YOLOv8 卓越的特征提取能力和训练时的数据增强（如亮度扰动），也能轻易通过物体表面的反光率、材质纹理将橡胶电缆与金属/工程塑料夹具区分开来。
    *   **多段碎片 Y 轴动态聚类 (Row-level Clustering)**：为解决物理夹具/立柱遮挡导致的“一根电缆被切分为多个 Bbox/Mask 碎片”问题，系统使用 Y 轴中心坐标动态聚类算法（$Y_{threshold} = 40px$），将水平线上的所有碎片归为同一层电缆，稳定归纳 4 层线缆。
    *   **主体段挑选 (Main Segment Selection)**：在同层线缆的多个碎片中，计算包围盒面积 $(W \times H)$ 并挑选面积最大者作为主体段，有效避开边缘残缺碎框的噪点干扰。
    *   **视野盲区与特写防护 (Active Scanning)**：若场景中捕获层数 $< 4$ 层（如近景特写视野），系统返回 `"status": "INCOMPLETE"` 状态，自动触发主动扫描流程。**优先控制机械臂保持当前姿态，纯沿 Z 轴上下平移**进行全局扫描。
2. **深度对齐与 2D 转 3D 全局映射**：
    *   **深度对齐到彩色 (Depth to Color Alignment)**：为了让 RGB 图上的 Bounding Box 像素坐标精确对应到物理深度，系统强制采用 **“深度图对齐到彩色图” (`rs.align(rs.stream.color)`)**。
    *   **抗黑洞深度提取 (Robust Depth Extraction)**：在选出的主体 Bbox 中心区域提取 10x10 像素的 ROI，剔除值为 0 的无效深度（黑洞），并取有效深度的**中位数 (Median)**，极大增强抗干扰能力。
    *   将该鲁棒深度值从 2D 像素面转化为相机坐标系下的 3D 坐标。
    *   结合手眼标定矩阵和当前机械臂位姿，将所有被扫描到的电缆坐标**统一映射到机械臂基座全局坐标系 (Base Frame)**。
3. **全局高度排序与过滤**：
    *   在基座坐标系中，对 4 根电缆的绝对高度 (Z 轴坐标) 进行排序。
    *   **剔除绝对高度最高的一根（即最上方的备用电缆）**。对剩余的 3 根电缆重新按绝对高度排序，分别定义为实际工作区域的“上”、“中”、“下”电缆。

### 4.2 手眼标定 (Hand-Eye Calibration)
*   采用经典的 Tsai-Lenz 或 Navy 算法解决 $AX=XB$ 问题。
*   通过拍摄标定板 (Aruco 或棋盘格) 获取 $T_{camera}^{target}$。
*   通过睿尔曼 API 获取机械臂末端位姿 $T_{base}^{end}$。
*   计算得出固定变换矩阵 $T_{end}^{camera}$。最终目标在基坐标系的位置为：
    $$P_{base} = T_{base}^{end} \times T_{end}^{camera} \times P_{camera}$$

### 4.3 动态避障与路径规划 (Obstacle Avoidance)
*   **深度图避障**：在机械臂伺服逼近目标的过程中，实时监控相机获取的深度图。
*   **人工势场法 (Artificial Potential Field)**：
    *   **算力优化**：执行 APF 前，对深度图进行近场裁剪（如仅保留 $Z < 30cm$ 的点云）并执行降采样（Downsampling），防止 Jetson 算力过载导致避障卡顿。
    *   将目标电缆设为**引力源**。
    *   将降采样后、距离相机小于安全阈值（如 15cm）的非目标障碍物映射到三维空间，设为**斥力源**。
    *   计算合成力向量，动态微调机械臂末端的移动速度和方向 (Velocity Control Mode)，实现柔顺避障。
*   **RRT算法(备选)**：如果是全局静态避障，可将深度点云转化为 OctoMap，利用 OMPL 库进行无碰撞路径规划。本项目倾向于动态局部避障（势场法响应更快）。

## 5. 异常处理与安全机制 (Error Handling)

针对机械臂任务中常见的“目标不可达”（超工作空间、奇异点、避障死锁等）问题，系统设计包含以下应对策略：
1. **运动学预检 (IK Pre-check)**：在向机械臂发送移动指令前，调用逆向运动学进行验证。若 IK 无解（超出物理工作空间），系统直接拦截指令，不予执行。
2. **姿态约束放宽 (Relax Orientation)**：对于必须到达但在固定姿态下不可达的目标坐标，算法允许对末端姿态（Roll, Pitch, Yaw）进行一定的角度放宽与妥协，以极大提升空间可达率。
3. **空间电子围栏 (Virtual Fence/Soft Limits)**：由于末端相机存在盲区，必须在控制底层建立绝对安全的空间约束（限制关节角和笛卡尔 XYZ 边界），防止机械臂手肘或基座连杆在移动时碰撞电缆柜。
4. **动态死锁逃逸**：在使用局部避障（如人工势场法）时，若机械臂陷入局部极小值导致长时间停滞，系统自动触发逃逸机制，加入随机扰动（Random Walk）或暂时切换至全局路径规划算法绕过死锁区域。
5. **安全回退与交互**：一旦系统确认目标绝对不可达、触碰电子围栏或捕获到 SDK 异常，机械臂立即停止并安全退回至初始观测点（Home Pose）。同时向上位机上报统一的错误状态 `{"result": "fail"}`。
6. **工业级日志追溯 (Logging)**：基于 `logging` 或 `loguru` 构建全局日志系统，将所有的 TCP 指令交互、IK 失败坐标、视觉丢失帧等核心事件全部落盘留存，保障撞机或异常时可完美溯源。

## 7. 后续建议
1. 由于电缆可能是柔性的且相互遮挡，建议相机在靠近过程中采用**视觉伺服 (Visual Servoing)**，即边走边识别动态更新目标点，而不是一次性计算死坐标。
2. RM65-6F 支持透传控制模式，在避障时通过下发速度指令比下发位置指令更为平滑。
